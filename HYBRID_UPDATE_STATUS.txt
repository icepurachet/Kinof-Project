สถานะการผสมระบบใน kinof2

ใช้ Backend NestJS/MySQL ของเรา ไม่แทนที่ด้วย Backend ของเพื่อน
Tracking: เว็บ/โปรแกรมที่บล็อกและโปรแกรมที่อนุญาตเลือกหมวดหมู่ได้ แสดงเป็นแท็ก
หมวด UT1 ยังคงนำเข้า/นำออกได้ จำกัดจำนวนโดเมนต่อหมวด
Face: เก็บ embedding ใน users.face_embedding เพื่อเทียบใบหน้า ไม่เก็บภาพต้นฉบับ
การจอง: สมาชิกคนใดคะแนนต่ำกว่า 50 จะไม่สามารถยืนยันการจองกลุ่มได้
Login: ยืนยัน OTP ก่อนรับ token แยกบัญชีผู้ใช้กับบัญชีผู้ดูแล
ตารางเรียน: นำเข้า Excel .xlsx หรือ CSV ใช้ student_id จริง ไม่ใช้เลขแถวแทนรหัสนักศึกษา
แอดมิน: เชิญให้ตั้งรหัสผ่านผ่านลิงก์ครั้งเดียว 30 นาที ส่งลิงก์ซ้ำได้
กู้รหัส: หน้า Forgot Password เลือกประเภทบัญชีได้ รองรับอีเมลเดียวกันคนละประเภท
SMTP: รองรับส่ง OTP และลิงก์ตั้งรหัส ต้องกรอกค่าผู้ส่งใน backend/.env ก่อน

อัปเดตฐานข้อมูล 004 แล้ว วันที่ 18 กันยายน 2026 หลังได้รับอนุญาต
เพิ่มโครงสร้างครบ 8 คำสั่ง สำรอง users/admins ก่อน และตรวจข้อมูลเดิมไม่เปลี่ยน
ผู้ใช้เดิม 7 บัญชี แอดมินเดิม 2 บัญชี รวมรหัสผ่านเดิมไม่เปลี่ยน
ไฟล์สำรอง: storage/database-backups/kinof-accounts-before-004-2026-09-18T16-43-52-973Z.sql
ยังต้องตั้งค่าระบบอีเมล และทดสอบกล้อง/Agent/Session ใช้งานจริง
ตรวจโดยไม่แก้ข้อมูล:
cd C:\Users\User\OneDrive\Desktop\kinof2\backend
node scripts/upgrade-accounts.cjs

หลังอนุญาตเท่านั้น ใช้คำสั่งนี้เพื่อสำรอง users/admins แล้วเพิ่มโครงสร้าง:
node scripts/upgrade-accounts.cjs --apply
หากสำรองล้มเหลว จะไม่เริ่มเพิ่มโครงสร้าง
MySQL ALTER TABLE ไม่ย้อนกลับอัตโนมัติ สคริปต์ตรวจช่องที่มีแล้วเพื่อรันต่อได้
บัญชีเดิมยังใช้ ID และรหัสผ่านเดิม ไม่เดาหรือสร้างรหัสนักศึกษาให้ข้อมูลเก่า

SMTP_HOST: โฮสต์ของผู้ให้บริการอีเมล
SMTP_PORT: ปกติ 587 (STARTTLS) หรือ 465 (TLS)
SMTP_SECURE: false สำหรับ 587 หรือ true สำหรับ 465
SMTP_USER: ชื่อบัญชีผู้ส่ง
SMTP_PASSWORD: App Password หรือข้อมูลรับรอง SMTP จากผู้ให้บริการ
SMTP_FROM: อีเมลผู้ส่งที่ผู้ให้บริการอนุญาต
ห้ามใส่ข้อมูลลับใน Git และห้ามคัดลอก .env.example ทับ .env เดิม
ถ้าไม่ตั้ง SMTP ยังใช้ webhook เดิมได้ ถ้าไม่มีทั้งสองในโหมดพัฒนาแสดงรหัส/ลิงก์ทดสอบ
Production ไม่แสดงรหัสทดสอบและต้องตั้งระบบส่งอีเมล

ติดตั้งไลบรารี Backend ที่เพิ่มแล้วในเครื่องนี้ ไม่ต้องติดตั้ง Python ใหม่
เมื่อโครงสร้าง DB พร้อม ให้เริ่ม Face Service, Backend และ Frontend ในคนละ Terminal
อีเมลจริง กล้องจริง และ Agent บล็อกจริงยังต้องทดสอบร่วมกับเครื่องและบัญชีผู้ส่ง
