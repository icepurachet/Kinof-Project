# KINOF Smart Lab Database

ชุดนี้คือฐานข้อมูลฉบับสุดท้ายตาม Flow ที่ตกลงกัน:

- นักศึกษาตามตารางเรียนเข้า Lab ได้จาก `subject_enrollments`
- ผู้จองไม่เลือกห้องและไม่เลือกที่นั่ง
- ระบบหา Lab ด้วย Load Balance และให้สมาชิกทั้งกลุ่มอยู่ห้องเดียวกัน
- การจองกลุ่มต้องรอสมาชิกตอบรับครบภายใน 5 นาที
- ห้องเดียวกันรับหลาย Booking ได้ ตราบใดที่จำนวนรวมไม่เกิน `rooms.capacity`
- เครื่องคอมพิวเตอร์เก็บใน `lab_computers`; ประวัติการเข้าใช้เก็บใน `pc_sessions`
- จำนวนผู้เรียนจริงนับจาก `subject_enrollments` ไม่เก็บตัวเลขซ้ำใน `subjects`

## ไฟล์ในชุดนี้

1. `kinof_finish_current.sql`
   ใช้ครั้งเดียวกับฐาน `kinof` ที่แก้ใน MySQL Workbench ตามขั้นตอนก่อนหน้านี้ เพิ่มกฎ, Index, View และตัวช่วย Load Balance ที่ยังขาด

2. `kinof_demo_seed.sql`
   ข้อมูลปลอมสำหรับ Demo เท่านั้น ไม่มีข้อมูลส่วนตัวจริง และไม่ควรรันในฐาน Production

3. `kinof_validation.sql`
   ตรวจโครงสร้าง ความสัมพันธ์ และข้อมูลผิดปกติแบบอ่านอย่างเดียว รันซ้ำได้

4. `kinof_schema_final.sql`
   โครงสร้างฉบับเต็มสำหรับสร้างฐานใหม่/ฐานว่างในอนาคต ไม่ใช่ไฟล์สำหรับอัปเดตฐานปัจจุบัน

## วิธีทำฐานปัจจุบันให้เสร็จ

ก่อนเริ่ม ให้สำรองข้อมูลด้วย MySQL Workbench: `Server > Data Export` แล้ว Export schema `kinof` เป็นไฟล์ SQL

จากนั้นเปิดและรันตามลำดับ:

1. `kinof_finish_current.sql`
2. `kinof_demo_seed.sql` เฉพาะเมื่อยืนยันว่าฐานนี้เป็นฐาน Demo และยังไม่มีข้อมูลจริง
3. `kinof_validation.sql`

ผลตรวจส่วนแรกของ `kinof_validation.sql` ควรเป็น `PASS` ทุกข้อ และชุดตรวจข้อมูลผิดปกติควรคืนค่า `0 rows` ทุกคำสั่ง

## สิ่งที่ View และ Procedure ทำ

- `v_subject_active_enrollments` นับจำนวนนักศึกษาสถานะ `active` ของแต่ละวิชา
- `v_booking_group_progress` สรุปสมาชิกที่ตอบรับ, รอตอบรับ, ปฏิเสธ และบอกว่ากลุ่มพร้อมค้นหาห้องหรือยัง
- `v_room_slot_usage` รวมจำนวนที่นั่งที่ถูกใช้โดย Booking สถานะ `confirmed`
- `sp_find_available_rooms(date, time_slot, seats)` คืนห้องที่ว่างและพอสำหรับทั้งกลุ่ม โดยเรียงแบบ Best Fit และตัดห้องที่มีตารางเรียนทับออก

ตัวอย่าง:

```sql
CALL sp_find_available_rooms('2026-09-09', '09:00-11:30', 3);
```

หมายถึงค้นหาห้องวันที่ 9 กันยายน 2026 รอบ 09:00-11:30 สำหรับ 3 คน

## ขอบเขตระหว่าง Database กับ Backend

Procedure ทำหน้าที่ค้นหาห้องที่เป็นไปได้ แต่ก่อนยืนยัน Booking จริง Backend ต้องเปิด Transaction, ตรวจจำนวนที่ว่างซ้ำ และล็อกข้อมูลห้องระหว่างอัปเดต เพื่อป้องกันผู้ใช้สองกลุ่มจองพร้อมกันจนเกินความจุ

ฐานข้อมูลเก็บกฎและข้อมูล ส่วน Flow 5 นาที, การแจ้งเตือน, การกด Accept, การเลือกผล Load Balance และ Transaction ยืนยัน Booking เป็นหน้าที่ Backend

## หมายเหตุข้อมูล Demo

- บัญชีและอีเมลทั้งหมดเป็นข้อมูลสมมติ
- `password_hash` ของ Admin เป็นข้อความ Placeholder ต้องให้ Backend สร้าง Hash จริงก่อนทดสอบ Login
- IP ใช้ช่วงสำหรับเอกสารตัวอย่าง และ MAC Address เป็นค่า Local/Demo
- ห้ามนำข้อมูลใบหน้าหรือรหัสลับจริงมาใส่ในไฟล์ Seed
